# Impeccable — design context

Brand tokens, type and voice live in `CLAUDE.md` (Brand guardrails). This file records the
who / why / how-it-should-feel that the code can't express. Update it when the answer changes.

## Design Context

### Users
- **Marketing site (`/`, `/curso-dj`, guías):** DJs in Viña del Mar / Valparaíso deciding
  whether to rent the room or take the course. Mostly phone, often from Instagram.
- **Booking (`/reservar`, `/reserva/estado`):** the same DJ, now paying. Phone-first; the
  moment is short and money is involved — clarity beats charm.
- **Customer account (`/cuenta`):** a returning DJ on their **phone, around a booking** —
  checking points or the next session right before/after reserving, usually arriving from a
  WhatsApp message or a confirmation email. Not a "portal session": get the number, see the
  next date, book, leave. Sign-in and sign-up are the same passwordless gesture (magic link
  on `/cuenta/login`, 6-digit code inline in the booking widget).
- **Admin (`/admin`):** the owner/staff running the room. Desktop-first tool surface.

### Brand Personality
Precise, direct, underground. Chilean Spanish, no filler. Gold is the everyday color on Ink;
Sirena is urgency only. Photography is low-key, single light source, real black.

### Aesthetic Direction
- **Marketing:** editorial — Big Shoulders display, one Fraunces italic line per section,
  photography with scrims, motion (MaskText/Ticker/Parallax).
- **Booking:** the same world, quieter: one column, one decision per step.
- **Customer account: "backstage pass."** Warm and personal — *you're a regular here*.
  Points read as a reward, not a ledger; the next session is the hero, not a table row.
  Same brand as the site, but explicitly **not the operator's tool**: it may share admin
  primitives (tokens, inputs, pills) for consistency and AA compliance, but the composition,
  copy and hierarchy should feel like something made for the DJ, not for staff.
- **Admin:** utilitarian tool surface (`data-surface="tool"`), dense, AA-tokened.
- Anti-references: generic SaaS dashboards (KPI-tile rows, card grids), "AI slop" glow/glass,
  Sirena used as decoration.

### Design Principles
1. **Phone-first for customers.** Every customer screen is designed at 375px first; desktop
   is the adaptation, not the other way round.
2. **One hero per screen.** In `/cuenta` that hero is the next session (or the points balance
   when nothing is booked) — not three equal stat tiles.
3. **Reward, not ledger.** Points copy and layout celebrate what the DJ earned; history is
   secondary and collapsible.
4. **Same gesture everywhere.** Sign-in = sign-up, passwordless, and the method should feel
   identical wherever it appears (login page, booking widget).
5. **Borrow tokens, not layouts.** Reuse admin primitives for contrast/type/touch-target
   guarantees (`lib/admin-a11y-contract.test.ts`), but never ship an admin page layout as a
   customer page.
